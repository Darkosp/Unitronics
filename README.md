# Unitronics — фабрички PLC систем

Едно репо, **две одделни апликации** што работат на два PLC контролери поврзани
на иста Ethernet мрежа и разменуваат податоци преку **Modbus TCP**.

| Папка        | Софтвер    | Хардвер    | Modbus улога |
|--------------|------------|------------|--------------|
| `UniLogic/`  | UniLogic   | UniStream  | **Master**   |
| `VisiLogic/` | VisiLogic  | Vision     | **Slave**    |

Двете апликации се самостојни — се компајлираат и се качуваат одделно.
Заедно се во едно репо затоа што се **еден систем**: секоја промена на
Modbus мапата мора да се направи во двете, во ист commit.

## Структура

```
UniLogic/   ,  VisiLogic/
  app/        →  живиот проект (.ulpr / .vlp) — изворот на вистината
  exports/    →  читливи извадоци: Modbus мапа, тагови, screenshot-и на ladder
  docs/       →  белешки специфични за таа апликација
docs/
  architecture.md          →  мрежа, IP адреси, Modbus регистарска мапа
  issues/                  →  документирани проблеми и нивна анализа
```

## ⚠ Важно за работа со Git

`.vlp` и `.ulpr` се **бинарни сопственички формати**. Тоа значи:

- ✅ Git ги чува, верзионира и може да врати стара верзија — тоа работи одлично.
- ❌ Git **не може** да покаже што точно е сменето (`git diff` е бескорисен).
- ❌ Git **не може** да спои (merge) две паралелни измени. Ќе има конфликт
  што се решава само со „земи ја едната, фрли ја другата".

**Последица — правила:**

1. **Еден човек по проект во исто време.** Никогаш две паралелни гранки врз
   истиот `.ulpr`.
2. **Секој commit опишува што е сменето со зборови.** Пораката на commit-от е
   единствената документација — Git не може да ја изведе сама.
3. **Пред секоја позначајна измена**, извези ја читливата состојба во
   `exports/` (Modbus мапа, листа на тагови). Тие се текст → нив Git
   ги диффира нормално и таму се гледа што се сменило.
4. **Секој commit одговара на состојба што е реално качена на PLC-то** (или
   јасно означи во пораката дека не е).

## Големи фајлови

Проектите можат да бидат десетици MB. Ако `app/` почне да расте, вклучуваме
Git LFS — види `docs/architecture.md`.
